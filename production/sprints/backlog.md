## 9. 任务领取规则

- 主控 Agent 接到用户需求 → **先在此处查找匹配任务或创建新任务**
- 启动 5 步工作流前应先看任务是否已存在
- 任务状态变更时同步更新本表（DoD 见 [12_LIFECYCLE.md](12_LIFECYCLE.md) §3）
- 完成的任务标 ✅ 并加 commit hash
- 取消的任务标 ❌ 并写取消原因

## 10. 任务流转触发表

| 触发条件 | 流转动作 |
|---|---|
| 用户提出需求 → 通过 DoR | ⏳ 待办 |
| 主控启动 5 步工作流 | ⏳ → 🚧 进行中 |
| feature-worker 报告完成 | 🚧 → 🔍 Review |
| reviewer 审查通过 | 🔍 → 🧪 QA |
| qa-tester 输出清单 + 用户手测通过 | 🧪 → ✅ 完成（commit hash 必填）|
| 任意阶段发现问题 | 回到 🚧 进行中 |
| 用户决定不做 | → ❌ 取消（原因必填）|
