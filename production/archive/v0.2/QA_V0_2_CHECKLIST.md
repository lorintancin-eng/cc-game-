## 1. Player

手测步骤：

1. 启动游戏，使用方向键或 WASD 持续移动 30 秒。
2. 贴近敌群后尝试绕圈、反向移动、穿过空隙。
3. 主动承受数次敌人碰撞伤害。

预期结果：

- 玩家移动方向响应正常，不出现卡死、瞬移或失控漂移。
- 玩家气血受到伤害后正确下降，死亡前仍可操作。
- 受击、死亡与通关状态不会同时触发。

失败判定：

- 玩家无法移动、输入无响应、碰撞后卡住。
- 气血显示与实际生存状态不一致。
- 控制台出现红色脚本错误。

## 2. Enemy

手测步骤：

1. 从开局观察 0:00-5:00 的普通敌人刷新。
2. 分别确认游魂、纸人妖、狐妖、石傀、鬼火等敌人能出现并追踪或移动。
3. 在 2:00、4:00 附近观察精英怪或阶段压力事件。

预期结果：

- 敌人能正常生成、移动、碰撞、受伤和死亡。
- 不同敌人表现出速度、血量、体型或移动模式差异。
- 精英怪出现后有可见差异，击败后奖励和击杀计数正常。

失败判定：

- 敌人不生成、生成后不移动、无法受伤或死亡。
- 刷怪密度失控导致明显卡顿或瞬间不可读死亡。
- 精英/特殊敌人缺资源、缺脚本或报错。

## 3. Weapon

手测步骤：

1. 开局确认默认追魂符自动攻击。
2. 通过升级选择解锁或强化飞剑、雷电符咒、八卦阵、爆裂符、山河印。
3. 在密集敌群中观察每个武器的命中、伤害、冷却和范围表现。

预期结果：

- 已解锁武器能自动生效，未解锁武器不会提前生效。
- 投射物、范围伤害、持续伤害和高冷却技能均能伤害敌人。
- 技能强化后效果有变化，且不会破坏其他武器。

失败判定：

- 武器不攻击、无法命中、伤害为 0 或造成脚本错误。
- 解锁状态和实际武器生效状态不一致。
- 单个技能导致大量残留节点、明显掉帧或碰撞异常。

## 4. XP / 升级

手测步骤：

1. 击杀敌人并拾取修为，观察修为条增长。
2. 触发多次境界提升，检查悟道选择面板。
3. 选择解锁项和强化项，确认后继续战斗。

预期结果：

- 修为拾取、经验增长、升级触发和暂停选择流程正常。
- 未解锁技能不出现对应强化项；解锁后可出现强化项。
- 选择升级后面板关闭，游戏恢复，效果正确应用。

失败判定：

- 修为无法拾取、升级不触发或重复触发。
- 升级面板卡住、无法选择或选择后不恢复游戏。
- 升级池出现空选项、重复异常或错误技能引用。

## 5. UI

手测步骤：

1. 开局查看 HUD 的气血、修为、境界、镇妖数、历劫时间。
2. 触发升级、BOSS 预警、死亡、通关界面。
3. 检查 UI 术语是否统一为 v0.2 神话包装。

预期结果：

- HUD 数值随游戏状态实时更新。
- 升级、BOSS 预警、死亡、通关 UI 层级清晰，互不遮挡关键操作。
- 文案不混用旧术语，如 HP、XP、Level、Game Over、Restart。

失败判定：

- HUD 不刷新、显示空文本或错位到屏幕外。
- 预警遮挡升级选择或死亡/通关界面同时出现。
- 关键按钮无法点击或键盘无法触发。

## 6. 计时

手测步骤：

1. 从新局开始记录历劫时间是否从 0:00 增长。
2. 在升级选择期间观察计时行为是否符合当前实现预期。
3. 到 4:30 和 5:00 分别观察预警和 BOSS 触发。

预期结果：

- 计时显示稳定递增，格式清晰。
- 阶段事件按时间只触发一次。
- 4:30 出现 BOSS 预警，5:00 生成 BOSS。

失败判定：

- 计时停止、跳变、负数或格式错误。
- 预警/BOSS 重复触发或完全不触发。
- 升级暂停后计时状态导致事件错乱。

## 7. 镇妖碑

手测步骤：

1. 在约 2:00 前后寻找镇妖碑生成位置。
2. 进入封印范围并保持停留，观察封印进度。
3. 中途离开范围，再重新进入完成封印。

预期结果：

- 镇妖碑单局只生成一次，范围和进度可见。
- 玩家在范围内推进封印，离开后暂停或衰减。
- 完成后奖励只发放一次，风险事件结束或恢复。

失败判定：

- 镇妖碑不生成、重复生成或进度不可见。
- 离开范围仍持续完成，或完成后可重复领奖。
- 风险刷怪无法结束、奖励破坏 XP/升级/HUD。

## 8. BOSS

手测步骤：

1. 存活到 5:00，确认荒年兽生成。
2. 观察追击、冲撞、怨火爆裂、召唤和低血暴怒行为。
3. 击败 BOSS，确认进入通关流程。

预期结果：

- BOSS 只生成一次，能追踪玩家、受伤、进入低血阶段并死亡。
- 技能有可读预警，召唤数量受控。
- BOSS 死亡后显示封印完成，不再按死亡结算。

失败判定：

- BOSS 不出现、重复出现、无法受伤或无法死亡。
- 技能无预警造成不可读伤害，或召唤导致刷怪失控。
- 击败 BOSS 后未通关，或通关与死亡 UI 同时出现。

## 9. 死亡 / Restart

手测步骤：

1. 主动让玩家死亡，观察死亡结算。
2. 点击或按键触发“再入劫境”。
3. 新一局开始后检查计时、敌人、武器、XP、UI 状态是否重置。

预期结果：

- 死亡后显示“道消身陨”等死亡状态，游戏停止或进入结算。
- Restart 能启动新局。
- 新局没有继承上一局的 BOSS、镇妖碑、敌人残留、升级面板或通关状态。

失败判定：

- 死亡后仍可继续战斗或重复触发死亡。
- Restart 无响应、报错或回到错误场景状态。
- 新局残留上一局节点、计时、奖励或 UI 状态。

## 10. 发布前检查

手测步骤：

1. 确认 `git status` 只包含本次计划发布的改动。
2. 从 Godot 编辑器打开项目，确认无导入错误和红色脚本解析错误。
3. 完成至少一次死亡 Restart 流程和一次 5 分钟通关流程。
4. 检查 release notes 已记录已执行验证、待执行验证、已知问题和发布阻塞项。
5. 在用户明确授权后，才允许执行 commit、push、tag、GitHub Release。

预期结果：

- 发布候选版本可从编辑器运行。
- 关键闭环可达成，控制台无红色错误。
- 版本说明与真实验证状态一致。
- Git 发布动作有用户明确授权记录。

失败判定：

- 存在未解释的脚本错误、场景引用错误或导入错误。
- 未完成完整死亡/Restart 或 BOSS 通关验证。
- release notes 与实际状态不一致。
- 未经授权执行 commit、push、tag 或 GitHub Release。
