## 0. 双会话协作契约（重要）

两个 Claude Code 会话同时在 `D:\new game` / 同一 `main` 上工作：

| | **内容会话（我）** | **美术会话（你）** |
|---|---|---|
| 拥有 | `scripts/` `scenes/`(新玩法) `resources/`(.tres) `design/gdd/` `design/quick-specs/` `production/` `tests/` `docs/architecture/` | `assets/` `design/style/` 现有 `.tscn` 的贴图/精灵接线 |
| 禁碰 | `assets/`、`design/style/`、美术资产 | 玩法脚本、数值 .tres、战斗逻辑 |

**Git 规则（双方都遵守）：**
1. **push 前先 `git pull --rebase origin main`**（吸收对方提交，避免分叉）。
2. 小步频繁提交（一个完整切片一提交），别攒大堆。
3. **`.tscn` 是唯一危险区**：我给新内容**一律建新场景**，不重构 `Player.tscn` / 现有敌人场景（那是你要贴图的）。万一必须动共享 `.tscn`，我在提交信息里标 `[shared-tscn]` 提示你。

> 理想做法：美术会话用独立 worktree（`git worktree`）隔离工作树；若同目录，务必各自只动自己那栏的文件。

## 2. 每切片执行法（CCGS 流程）

1. **设计**：复用 `character-system.md` 模式 + 每角色 `quick-design` 规格（公式/武器行为定死）。
2. **实现**：建角色 `.tres` + 武器脚本 + 角色脚本 → 接入选择 UI / 升级池 / HUD。
3. **测试**：公式/行为 GUT 单测 + Main.tscn 集成测试（接线验证，复用新建的集成 harness）。
4. **闭环**：`pull --rebase` → commit → push → **CI 绿**。
5. **检查点**：更新 `active.md`。
